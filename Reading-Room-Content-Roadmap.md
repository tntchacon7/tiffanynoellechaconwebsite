# Reading Room Content Roadmap — R5

Tiffany Noelle Chacon author site · R5 (Clean Romance Reading Room foundation)

This is the proposed next wave of Reading Room guides, per the R5 brief's Part 13. Nothing here is written or published yet — R5 ships only the hub and the cornerstone "What Is Clean Romance?" guide. Every "which Tiffany books can legitimately appear" answer below is pulled directly from the approved `src/data/catalog.js` (exact `tropes`/`sport`/`series` fields, re-checked live while writing this document, not from memory) — no book is placed in a category based on a guess.

## Cross-cutting notes for whoever drafts these next

1. **Three trope guides (#6, #7, #8) and one seasonal guide (#9) all share books with the sport/series guides.** Before drafting any of them, decide one rule and apply it consistently — e.g., "a book's primary guide is its sport or series; trope/seasonal guides mention and link to it rather than re-profiling it in full." This avoids duplicate, competing copy for the same title living on two URLs.
2. **Two guides (hockey, marriage of convenience) currently have only one eligible Tiffany book each.** Publishing either as a "best of" list with a single title and no verified outside books would misrepresent it as more comprehensive than it is — either wait for outside verification or reframe as a shorter, honestly-scoped piece.
3. **All nine guides should use `GuideLayout` and the shared guide components** (`Breadcrumbs`, `EditorialCallout`, `PullQuote`, `RelatedReading`) built in R5 — no new layout infrastructure should be needed for any of them.
4. **None of the nine are Tiffany-only by design** — per the brief, the Reading Room is meant to grow beyond her own catalog. Every "outside-book research required" note above is a real, unstarted task, not a placeholder.

## Future recommendation data model (Part 15)

The brief asks for a proposed minimal schema for future recommended books by other authors, without building a database now. Proposed shape, for whenever the first outside-author recommendation is actually added:

```js
{
  title: string,
  author: string,
  cover: { image: string | null, alt: string | null }, // null until a cover image is actually sourced/licensed
  url: string | null,               // publisher/author or retailer page
  affiliateUrl: string | null,      // only populated once a real affiliate link + disclosure are in place
  contentLevel: "kisses-only" | "closed-door" | "fade-to-black" | "needs-verification",
  verification: {
    status: "verified" | "likely" | "unverified",
    source: string | null,          // e.g. "Tiffany read it", "author's stated content promise", "reader-reported, unconfirmed"
  },
  subgenre: string[],                // e.g. ["sports", "hockey"]
  tropes: string[],
  sport: string | null,
  setting: string | null,
  editorialNote: string,             // short, honest note — see the two note styles below
  tiffanyPersonallyRead: boolean,
  isTiffanyOwnBook: boolean,         // drives the disclosure treatment — must always render clearly when true
  disclosure: string | null,         // required text if affiliateUrl is set (Amazon Associate language, matching the site's existing footer disclosure convention)
}
```

Two rules carried over directly from the brief, worth restating here since they're easy to lose once a real database exists:

- **"Tiffany's Take"** language is reserved for books where `tiffanyPersonallyRead` is `true`. For everything else, use neutral framing — "Why It May Be a Fit" or "Why Readers May Like It" — never a first-person endorsement she didn't actually give.
- **`isTiffanyOwnBook: true`** must always render a clear, unmistakable "this is one of Tiffany's own books" marker in any future recommendation list — never presented as if it were a neutral third-party pick alongside outside authors.

No table, JSON file, or CMS was built for this in R5 — this is a schema proposal only, for whoever builds the first real recommendation article next.
